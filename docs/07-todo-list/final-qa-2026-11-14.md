# 최종 종합 QA — 2026-11-14

## 결과

**검사한 범위의 기능 검증은 통과했다.** 설명과 결과 표시에서 세 항목을 발견해 수정하고, 같은 상황을 다시 재현해 확인했다. 모든 가능한 입력·브라우저·장시간 사용에서 결함이 없다는 보증을 의미하지 않는다.

대상은 QA 당시 `feature/summary-playback`의 로컬 작업 폴더와 `http://127.0.0.1:5003`이다. QA 종료 시점에는 수정이 로컬 상태였고 커밋·PR·병합은 진행하지 않았다. 이후 원격 반영 상태는 Git 이력과 PR에서 확인한다. Playwright MCP는 사용하지 않았다.

## 직접 확인한 범위

실제 Chromium과 실제 Flask 서버를 연결했다. 테스트 응답으로 화면만 채우는 방식과 구분해, 브라우저에서 폼 제출·실제 HTTP 응답·장면 이동·기록 조회 결과를 대조했다.

- **예제 5개 × 알고리즘 모드 3개 = 15개 풀이 흐름**, 비교의 양쪽을 포함해 20개 알고리즘 실행 확인.
- 각 실행에서 발표용 요약·단계별 요약·전체 기록을 전환. 발표 장면 **136개**, 단계별 요약 **356개**에서 수식·문자 배정·설명·계산식과 서버의 실제 이벤트가 일치함을 검사.
- 같은 탭에서 모든 예제와 모드를 연속 전환. 이전 수식이 계산판을 덮어쓰지 않고, 활성 재생 타이머가 현재 패널 수를 넘지 않는지 확인.
- 전체 기록의 처음, 200→201 페이지 경계, 201→200 역방향 경계, 실제 마지막, 처음부터 다시 보기 확인. SEND 완전탐색은 80,001번째와 **7,748,195번째 실제 종료 이벤트**까지 접근.
- 자동 재생의 끝까지 진행·자동 정지·다시 시작·일시정지와 상대 비교 패널의 위치 유지 확인.
- 빈 입력·다른 연산자·숫자 포함·11종 문자·129자 입력의 클라이언트 차단, 소문자·공백 정규화 확인.

## 발견하고 수정한 항목

### QA-01 — 해 없음 설명의 잘못된 전제

- 재현: A + B = AA → 백트래킹 → 마지막 발표 장면.
- 문제: 정답이 0개인데 구조 설명에 “정답을 찾은 뒤”라고 적혀 있었다.
- 수정: 해의 유무와 무관하게 남은 후보 검사가 모두 끝났다는 표현으로 변경.
- 검증: 수정 전 회귀 테스트 실패, 수정 후 통과. 실제 마지막 장면에서 정답 0개와 종료 설명을 재확인.
- 화면: [수정 전](verification-assets/qa-no-solution-before.png), [수정 후](verification-assets/qa-no-solution-after.png).

### QA-02 — 완전탐색의 검사 방식 설명

- 재현: I + BB = ILL → 완전탐색 → 정답 장면.
- 문제: 완전탐색에도 백트래킹과 같은 자리 계산·마지막 올림 검사 설명을 사용해 알고리즘 동작을 혼동시킬 수 있었다.
- 수정: “전체 덧셈식이 성립합니다”로 제목을 구분하고, 완성 배정의 전체 식을 비교하며 자리별 중간 검사로 후보를 줄이지 않는다고 설명.
- 검증: 수정 전 회귀 테스트 실패, 수정 후 통과. 실제 브라우저에서 변경된 제목과 구조 설명 확인.
- 화면: [수정 전](verification-assets/qa-brute-description-before.png), [수정 후](verification-assets/qa-brute-description-after.png).

### QA-03 — 종료·정답 화면에 남는 대기/후보 메타데이터

- 문제: 완료된 해 없음 화면에도 “자리 선택 전”, “아직 배정된 숫자가 없습니다”가 남았다. 정답 발견/완료도 대기 상태처럼 표시됐고, 제한 중단 후 발견한 정답을 보여줄 때 이전 후보의 자리 강조와 올림이 붙을 수 있었다.
- 수정: 정답 발견·최종 정답·탐색 종료·발견한 정답을 구분한다. 결과 계산판을 보여줄 때 이전 후보의 강조와 올림을 제거하고, 해 없음 종료에는 유효한 배정이 없다는 안내를 표시한다.
- 검증: 실제 완료/해 없음 화면 재확인. 제한 상태는 실제 Flask 응답의 `TRACE_LIMIT=2`, `SOLUTION_LIMIT=1` 조건으로 DOM 회귀 검증. 네 개 검증이 수정 전 실패, 수정 후 통과했다.
- 해 없음 화면의 전후 근거는 QA-01의 이미지에도 포함된다.

## 복구·예외 흐름

1. **연결 실패 후 재시도:** 브라우저 fetch에 한 번 연결 오류를 주입해 UI 오류 처리를 확인한 뒤, 실제 서버 요청으로 재시도 성공. 입력과 알고리즘 선택이 다시 활성화됐다. 실제 네트워크 단절 시험과는 구분한다.
2. **기록 만료:** 현재 풀이를 둔 채 다른 실제 요청 5개로 토큰을 교체했다. 이전 전체 기록은 실제 `404 TRACE_EXPIRED`를 반환했고, UI는 안내와 사용 가능한 요약을 유지했다. 재풀이 후 새 전체 기록 조회 성공.
3. **여러 해 선택:** A + B = C의 32개 중 두 번째 해를 선택해 실제 반환 숫자식과 일치하는지 확인. 탐색 장면 위치는 변경되지 않았다.
4. **늦은 이전 응답:** I + BB의 실제 전체 기록 응답을 브라우저에서 1.5초 지연시킨 상태로 SEND로 전환했다. 응답이 늦게 도착해도 SEND 수식과 새 보기를 덮어쓰지 않았다.

이 과정에서 콘솔에는 의도적으로 만료시킨 기록의 HTTP 404가 한 번 기록됐다. 예상한 오류 응답으로 UI가 복구했으며, 나머지 검사에서 새 JavaScript 예외는 확인되지 않았다.

## 한계와 후속 작업

현재 PC의 Chromium과 뷰포트 기반 검사다. 다른 브라우저, 실제 휴대기기·스크린리더, 장시간 메모리/동시 부하, 새 PC의 깨끗한 설치, 발표장 프로젝터와 실제 5분 리허설은 이번 검사에 포함하지 않았다. 특히 시간 제한은 CPU 부하에 따라 적용될 수 있으므로 실제 발표 PC에서도 실행 확인이 필요하다.

검사 범위에서는 수정 후 추가로 재현되는 동작 오류가 없었다. PPT·영상 완성 여부나 원격 브랜치 반영까지 완료됐다는 의미는 아니다.
