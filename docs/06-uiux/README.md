# 06. UI/UX 설계

> 현재 구현의 동작과 표현 규칙이다. 핵심은 실제 알고리즘 동작의 이해다.

## 화면 구성과 시각 방향

16:9 발표 화면에서 제목과 입력·예제·알고리즘 선택·실행을 상단에, 세로셈과 현재 자리/올림을 중심에 배치한다. 옆에는 현재 배정과 단계 설명을 두고 아래에는 탐색 기록, 재생 컨트롤, 결과와 비교를 배치한다. 화면이 좁을 때 영역을 세로로 쌓아 가로 스크롤을 줄인다. 관리 페이지처럼 반복 카드로 나누기보다 계산식에 시선을 모은다. 읽기 쉬운 글자, 명확한 위계, 절제된 색과 자연스러운 전환을 사용하고 과도한 파란 배경은 피한다. 검사 중·성공·실패를 색뿐 아니라 텍스트와 기호로 구분한다. 버튼은 키보드 접근과 포커스 표시를 제공하고 모션 축소 설정을 존중한다.

## 입력과 실행

입력창은 빈 상태로 시작하며 `I + BB = ILL`, `SEND + MORE = MONEY`, `A + A = A`, `A + B = C`, `A + B = AA` 예제 버튼을 제공한다. 선택은 입력창만 채우고 실행 버튼이 서버 풀이를 시작한다. 브라우저 검사 → 수식 분석 및 서버 계산 중 표시 → 기록 표시 → 결과 순으로 진행한다. 빈 입력, 잘못된 형식, 숫자 포함, 문자 10개 초과, 길이 초과 등의 원인과 수정 방법을 입력창 근처에 표시한다. 오류는 색상만으로 전달하지 않는다. 중복 요청을 막고 새 실행 시 이전 결과와 재생 상태를 초기화한다.

## 시각화와 제어

기본 보기는 **발표용 요약**이다. 실제 기록에서 설명 장면을 구성해 계산판과 큰 제목·한 문장 설명·계산식·구조 설명을 함께 보여 준다. 기본 예제에서는 4~10개 장면이며, 실제로 발생하지 않은 실패·정답은 추가하지 않는다. 구조 설명은 현재 장면에서 숫자 배정·제약 검사·복귀·자리올림이 연결되는 원리를 다룬다. 다음 장면, 이전, 번호 목차, 좌우 방향키로 직접 넘길 수 있다. 목차 옆의 독립된 자동 재생 버튼은 1×에서 장면당 약 6초로 끝까지 진행하며, 재생 중에는 일시정지, 마지막에는 다시 자동 재생으로 바뀐다. 발표용 요약은 자동으로 시작하지 않으며 수동 이동 시 자동 재생을 멈춘다. 장면마다 현재 수식의 실제 스냅샷을 사용하며, 실패·되돌리기 다음에는 재시도 장면으로 후보 변경을 설명한다. 해 없음·제한 중단도 독립된 마무리 장면으로 안내한다.

기존 상세 동작은 **단계별 요약**, 원본 전체 구간은 **전체 기록**으로 별도 선택한다. 발표 화면에서는 큰 원본 단계 수와 세부 목록·외부 결과 영역을 접어 정답을 미리 드러내지 않고, 장면의 마무리에서 정답·검사 수를 설명한다. 두 알고리즘의 장면 이동은 서로 독립적이다.

문자별 배정과 세로셈에서 현재 검사 자리를 강조하고 입력·출력 올림을 별도로 표시한다. 후보 선택, 배정, 자리 계산, 올림 검사, 충돌·이유, 가지치기, 복귀, 해 발견을 실제 이벤트에서 설명한다. 탐색 기록 또는 트리는 현재 경로와 인접한 분기만 표시하고 나머지는 접어 과밀을 피한다. 이벤트가 잘리면 재생 가능한 기록이 일부임을 표시한다.

전체 보기와 중요 요약 보기를 제공한다. 요약은 대표 이벤트 몇 개로 건너뛰지 않고 배정·검사·실패·복귀가 이어지는 짧은 장면들을 원래 순서대로 보여 준다. 장면이 바뀌거나 정답·종료를 공개하기 전 자동 재생을 멈추고 다음 장면 버튼으로 이어간다. 생략한 단계 수와 바뀔 문자 배정을 미리 안내한다. 1×에서 일반 배정은 1초, 계산·올림·충돌·가지치기·전체 식 검사·정답은 1.5초 동안 유지하며 0.5×·2×·5×에 따라 비례 조정한다. 발생하지 않은 이벤트는 만들지 않는다. 생략한 개수와 현재 보기의 연속된 단계 번호를 표시하고 원본 기록 번호는 보조 정보로 제공한다. 보기 전환 시 해당 패널의 재생을 멈추고 첫 단계로 이동한다. 비교 모드에서는 두 알고리즘의 패널을 나란히 두고 각각 재생하며, 좁은 화면에서는 세로로 배치한다. 각 패널에 자동 재생, 일시정지, 이전·다음, 속도 변경, 처음부터 다시 보기를 제공한다. 이전과 다음은 이벤트 스냅샷을 사용해 정확히 복원하고 양 끝에서는 해당 버튼을 비활성화한다. 마지막 단계에서는 다시 재생 버튼으로 처음부터 볼 수 있다. 요약에서는 재시작에 새 풀이를 요청하지 않으며 전체 보기의 첫 페이지가 메모리에 없으면 기록 조회만 수행한다.

마지막 기록을 재생하면 발견한 해가 있는 경우 계산판에도 해당 정답을 표시한다. 실제 탐색 완료 여부는 별도 안내로 구분하며, 시간·해 제한으로 중단된 경우 완료라고 표시하지 않는다. 각 패널의 재풀이 버튼으로 해당 알고리즘 하나만 재계산할 수 있고 상대 패널의 재생 상태는 유지한다. 요약 화면은 요약만 먼저 전송하고 전체 보기 선택 시 실제 실행 기록을 200개씩 조회한다. 페이지 경계를 넘어 이전·다음·자동 재생을 계속할 수 있고, 전체 단계 번호와 마지막 단계 버튼으로 직접 이동할 수 있다. 80,000개 초기 버퍼 상한이 전체 보기의 재생 범위를 자르지 않는다.

발표 화면 버튼은 소개·입력 영역을 접고 두 계산판과 제어·현재 단계 설명을 밀집 배치한다. 다시 일반 화면으로 전환할 수 있다. 발표 화면에서는 인접 기록 대신 선택한 기록만 표시하며 좁은 화면의 비교 패널은 세로 배치한다.

## 결과와 제한

계산판의 상태 표시는 정답 발견·최종 정답·탐색 종료·발견한 정답을 구분한다. 정답을 표시할 때는 이전 후보의 자리 강조와 올림을 남기지 않는다. 해가 없는 종료 상태를 아직 실행하지 않은 대기 상태로 표시하지 않는다.

요약에서 같은 후보의 자리 계산 직후에는 같은 배정의 자리올림을 보여 준다. 다른 후보로 바꾸려면 기존 숫자를 해제하고 새 숫자를 배정하는 실제 이벤트가 있어야 한다. 단순히 1.5초씩 멈추거나 생략 수를 표시하는 것으로 이 연속성을 대체하지 않는다. 정답을 찾은 뒤 다른 실패 후보로 되돌아가는 임의 구간은 요약에서 제외한다.

원문, 숫자 계산식, 문자 배정, 해 수, 후보 시도 수, 검증·가지치기 횟수 및 시간을 표시한다. 반환된 여러 해는 선택해 확인하되 기록이 전체 탐색에 대한 것임을 밝힌다. 탐색 완료 후 해가 없으면 모든 허용 후보에서 유효한 배정을 찾지 못했다고 설명한다. 시간·해 상한으로 중단되면 미완료와 발견된 해 수의 하한을 표시하고 해가 없다고 단정하지 않는다. 기록 잘림은 탐색 중단과 별도로 안내한다. 비교는 양쪽의 상태와 측정 기준 및 기록 생성 비용을 함께 표시한다.
