# 06. UI/UX 설계

> 구현 전 제안. 핵심은 실제 알고리즘 동작의 이해다.

## 화면 구성과 시각 방향

16:9 발표 화면에서 제목과 입력·예제·알고리즘 선택·실행을 상단에, 세로셈과 현재 자리/올림을 중심에 배치한다. 옆에는 현재 배정과 단계 설명을 두고 아래에는 탐색 기록, 재생 컨트롤, 결과와 비교를 배치한다. 화면이 좁을 때 영역을 세로로 쌓아 가로 스크롤을 줄인다. 관리 페이지처럼 반복 카드로 나누기보다 계산식에 시선을 모은다. 읽기 쉬운 글자, 명확한 위계, 절제된 색과 자연스러운 전환을 사용하고 과도한 파란 배경은 피한다. 검사 중·성공·실패를 색뿐 아니라 텍스트와 기호로 구분한다. 버튼은 키보드 접근과 포커스 표시를 제공하고 모션 축소 설정을 존중한다.

## 입력과 실행

입력창 옆에 `I + BB = ILL`, `SEND + MORE = MONEY` 예제 버튼을 제공한다. 선택은 입력창만 채우고 실행 버튼이 서버 풀이를 시작한다. 브라우저 검사 → 수식 분석 및 서버 계산 중 표시 → 기록 표시 → 결과 순으로 진행한다. 빈 입력, 잘못된 형식, 숫자 포함, 문자 10개 초과, 길이 초과 등의 원인과 수정 방법을 입력창 근처에 표시한다. 오류는 색상만으로 전달하지 않는다. 중복 요청을 막고 새 실행 시 이전 결과와 재생 상태를 초기화한다.

## 시각화와 제어

문자별 배정과 세로셈에서 현재 검사 자리를 강조하고 입력·출력 올림을 별도로 표시한다. 후보 선택, 배정, 자리 계산, 올림 검사, 충돌·이유, 가지치기, 복귀, 해 발견을 실제 이벤트에서 설명한다. 탐색 기록 또는 트리는 현재 경로와 인접한 분기만 표시하고 나머지는 접어 과밀을 피한다. 이벤트가 잘리면 재생 가능한 기록이 일부임을 표시한다.

실행/자동 재생, 일시정지, 이전·다음, 속도 변경, 처음부터 다시 보기를 제공한다. 이전과 다음은 이벤트 스냅샷을 사용해 정확히 복원하고 양 끝에서는 해당 버튼을 비활성화한다. 새 실행과 재시작의 차이를 명확히 한다. 재시작은 서버를 다시 호출하지 않고 기록의 처음으로 이동한다.

## 결과와 제한

원문, 숫자 계산식, 문자 배정, 해 수, 후보 시도 수, 검증·가지치기 횟수 및 시간을 표시한다. 반환된 여러 해는 선택해 확인하되 기록이 전체 탐색에 대한 것임을 밝힌다. 탐색 완료 후 해가 없으면 모든 허용 후보에서 유효한 배정을 찾지 못했다고 설명한다. 시간·해 상한으로 중단되면 미완료와 발견된 해 수의 하한을 표시하고 해가 없다고 단정하지 않는다. 기록 잘림은 탐색 중단과 별도로 안내한다. 비교는 양쪽의 상태와 측정 기준 및 기록 생성 비용을 함께 표시한다.
