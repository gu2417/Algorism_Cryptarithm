# 03. 아키텍처

> 현재 구현의 구조와 실행 계약이다. 서버는 Flask, 알고리즘은 Python, 브라우저는 HTML/CSS/JavaScript로 구성된다.

## 흐름과 책임

```text
입력/예제 → 브라우저 형식 검사 → Flask API → 서버 검증·파싱
 → 선택 알고리즘 → 해·통계·실제 이벤트 → JSON → 재생·결과 표시
```

서버가 숫자 배정과 모든 제약 검사 및 정답 검증을 담당한다. 브라우저는 입력 형식을 안내하고 응답을 시각화하며 풀이 로직을 중복하지 않는다. [계층과 의존성](../04-file-structure/README.md)을 따른다.

## 파싱과 풀이

1. 원문 길이를 검사하고 소문자를 대문자로 정규화한 뒤 전체 문법 `WORD + WORD = WORD`를 검사한다. 세 단어, 서로 다른 문자 집합 및 여러 자리 단어의 선행 문자를 추출한다. 10종 초과는 오류다.
2. 완전탐색은 결과 단어의 문자부터 사용 가능한 숫자를 중복 없이 배정하고 선행 0을 제외한 뒤 완성된 배정의 전체 산식을 검사한다. 문자 순서만 달라지며 가능한 배정을 빠짐없이 탐색한다. 부분 자리 계산을 이용한 가지치기는 하지 않는다. 문자별 십진수 자리 계수를 미리 구해 배정 시 합계를 갱신하고, 완성 배정에서 전체 식의 차이가 0인지 검사한다. 기록 상한 이후에는 같은 후보와 전체 식 검사를 계속하되 저장되지 않을 스냅샷 생성을 생략한다. 이 경로에서도 해와 통계·원본 이벤트 순서는 동일하다.
3. 백트래킹은 오른쪽 자리부터 두 피연산자와 결과의 문자를 읽는다. 없는 피연산자 자리는 0으로 취급한다. 현재 자리에서 아직 배정되지 않은 피연산자 문자에 남은 숫자를 순서대로 시도한다. 같은 문자가 반복되면 이미 선택한 값을 재사용한다.
4. `합 = 왼쪽 숫자 + 오른쪽 숫자 + 입력 올림`, `결과 숫자 = 합 % 10`, `출력 올림 = 합 // 10`이다. 결과 문자가 이미 배정된 숫자와 다르거나, 새 결과 숫자가 다른 문자에 이미 사용됐거나 선행 0이면 해당 후보를 버린다. 그 외에는 필요한 결과 배정을 하고 다음 자리로 재귀한다.
5. 모든 단어의 마지막 자리 이후 올림이 0이고 전체 산식과 일대일 배정·선행 0 규칙을 재검증하면 해다. 복귀 시 이 호출에서 새로 배정한 문자만 역순으로 해제한다. 해를 찾은 뒤에도 종료 조건까지 계속해 여러 해를 찾는다.

예를 들어 일의 자리 `D + E = Y`에서 `D=7`, `E=5`이면 `Y=2`, 다음 자리 올림은 1이다. `Y`가 이미 2가 아니거나 2가 다른 문자에 쓰였다면 더 높은 자리 배정은 시도하지 않는다. 이렇게 일찍 불가능한 접미 자리의 모든 상위 자리 후보를 줄인다. 최종 자리 이후 올림이 남아도 실패한다.

서로 다른 문자 수를 `k ≤ 10`, 최대 단어 길이를 `L`이라 하면 완전탐색의 최악 시간은 배정 열거와 검증에 대해 `O(P(10,k) × L)`이고 배정 상태 공간은 `O(k+L)`이다. 자리별 백트래킹도 최악에는 `O(P(10,k) × L)` 수준이며 가지치기는 최악 복잡도를 바꾸지 않는다. 재귀·문제·배정 상태는 `O(k+L)`이고 반환 해와 기록은 별도 상한까지 추가 메모리를 쓴다. 문자열 길이 제한은 재귀 깊이도 제한한다.

## 제한과 측정

기본 설정: 알고리즘별 독립적인 단조 시계 제한 5초, 반환 해 최대 100개, 알고리즘별 초기 스냅샷 버퍼 최대 80,000개 이벤트. 백트래킹은 후보와 재귀 진입에서, 완전탐색은 깊이 0~3의 진입 및 탐색 종료에서 기한을 협조적으로 확인한다. 깊이 3 아래의 작은 부분 트리를 처리하는 동안 미세한 제한 초과가 가능하다. 버퍼 상한에 도달하면 추가 스냅샷 저장만 중단하고 계산과 요약 수집은 계속한다. 웹 전체 보기는 버퍼 밖의 실제 실행 기록도 복원해 조회한다. 시간 또는 해 상한에 도달하면 해당 탐색을 중지한다. 제한값은 설정으로 조정하며 운영 환경에 따라 검증한다. 동기 요청이므로 제한은 강제 프로세스 중단을 보장하지 않는다. 비교 시 두 실행의 시간과 버퍼를 각각 제한한다. 기록과 응답 크기가 커지는 비용이 있다.

`status`는 `complete`, `time_limit`, `solution_limit`이다. `complete`만 정확한 전체 해 개수를 의미한다. 제한 시 반환된 해 개수는 하한이며 0이어도 해 없음으로 단정하지 않는다. `trace_truncated`는 즉시 반환하는 기록 버퍼의 절단 여부로 계산 완료 여부와 독립적이다. 웹의 요약 요청은 아카이브로 전체 조회가 가능하므로 이를 false로 반환하고, 버퍼 상한 도달 여부는 `trace_buffer_limited`에 보존한다. 레거시 즉시 반환 경로만 저장된 접두 구간에 제한되며 웹 전체 보기는 해당 실행이 실제 도달한 모든 이벤트를 조회한다. 카운트는 각 알고리즘에서 **문자에 미사용 숫자를 배정하려 시도한 횟수**로 정의하며, 검증 횟수와 가지치기 횟수는 별도다. 완전탐색의 가지치기에는 선행 0 거부를 포함하고 자리 검사 가지치기는 없다. 실행 시간은 해당 알고리즘 호출 시작부터 종료까지 단조 시계로 측정하며 HTTP 전송과 브라우저 재생은 제외한다. 완전탐색 계수의 사전 계산 비용도 실행 시간에 포함된다. 두 알고리즘의 실행 시간에 기록 생성 비용이 포함된다.

## Flask API 제안

`POST /api/solve` JSON 요청: `{"expression":"SEND + MORE = MONEY","algorithm":"backtracking"}`. `algorithm`은 `backtracking`, `brute_force`, `compare` 중 하나다. compare는 동일 문제로 두 알고리즘을 독립 실행하고 각각의 기록을 반환한다. 서버가 상한을 결정하며 요청마다 새 실행이다.

성공 `200`: `original_expression`, `normalized_expression`, `runs` 배열. 각 run은 `algorithm`, `status`, `solutions`(문자-숫자 `mapping`, `numeric_expression`), `solutions_found`(반환된 해 개수), `statistics`(아래), `trace` 및 `trace_truncated`를 포함한다. `statistics`는 `assignment_attempts`, `complete_assignments_checked`, `prunes`, `elapsed_ms`다. complete일 때 `solutions_found`가 총 해 수이고 그 외에는 하한이다. 두 알고리즘 모두 실제 탐색 기록을 반환한다. 유효하지 않은 요청은 `400`과 `{"error":{"code":"INVALID_FORMAT","message":"..."}}`; 유형에 따라 `EMPTY_INPUT`, `TOO_LONG`, `INVALID_FORMAT`, `TOO_MANY_LETTERS`, `INVALID_ALGORITHM`을 사용한다. 예상치 못한 오류는 `500`과 일반 오류 메시지를 반환하며 내부 상세는 서버 로그에만 둔다. 시간 및 해 제한은 정상적인 부분 결과로 `200`을 사용한다.

## 기록과 재생 계약

`presentation_scenes`는 발표용 장면 배열이다. 각 장면은 실제 `summary_trace`의 `event` 스냅샷, `phase`, `title`, `narration`, `formula`, `detail`, `explanation`을 가진다. `explanation`은 발표 조언 대신 현재 장면의 세로셈 구조, 숫자 배정표, 제약 검사, 재귀 복귀, 나머지·몫에 의한 결과와 올림 전달을 설명한다. 원본 순번 순서를 유지하며 문제·배정·실패·복귀·재시도·대표 자리 계산·정답·종료 중 실제로 존재하는 장면만 제공한다. 자리 계산 설명은 해당 스냅샷의 숫자와 입력 올림으로 계산하고, 결과 문자가 새로 배정되는 경우 그 실제 assign 이벤트를 사용해 계산판에도 결과 숫자가 보이게 한다. 제한 중단은 전체 완료로 설명하지 않는다.

백트래킹 이벤트는 `seq`(0부터 연속), `type`, `depth`, `assignment`(이벤트 직후 전체 배정 스냅샷), `column`(일의 자리 0, 해당 없으면 null), `carry_in`, `carry_out`, `check`(결과 또는 null), `reason`(충돌·가지치기 이유 또는 null), `undo`(복귀 시 해제한 문자 목록), `is_solution`을 가진다. 적용되지 않는 필드는 null 또는 빈 배열이다. 이벤트 종류는 `start`, `candidate`, `assign`, `column_calculation`, `carry_check`, `conflict`, `prune`, `backtrack`, `solution`, `finish`다. 깊이는 현재 재귀 호출 깊이이며 각 이벤트는 그 순간의 상태를 나타낸다. 제한으로 `finish`가 기록에 없을 수 있으므로 종료 상태는 항상 run의 `status`로 판단한다.

완전탐색은 같은 필드 형식으로 후보 선택·배정·선행 0 제외·복귀·정답과 종료를 기록한다. `complete_check` 이벤트는 완성된 숫자식과 검증 결과를 담으며 `column`, `carry_in`, `carry_out`은 항상 null이다. 개별 자릿수 검사나 자리올림 가지치기를 수행하지 않는다. 비교 모드에서는 두 기록을 독립적인 패널에서 각각 재생한다.

`summary_trace`는 `Feature/summary.py`에서 실제 실행 아카이브를 바탕으로 구성한다. 임의의 앞·중간·뒤 구간을 연결하지 않는다. 대표 실패 후보의 배정·검사·해제와 첫 정답에 이른 실제 배정 경로를 선택한다. 인접 요약 이벤트 사이의 배정 변화는 해당 assign 또는 backtrack으로 설명되어야 하며, 같은 자리 계산과 carry_check는 같은 후보의 연속 원본 이벤트로 유지한다. 정답 발견 뒤에는 다른 실패 후보를 끼워 넣지 않고 실제 finish로 마무리한다. 해가 없으면 대표 실패 과정과 실제 종료를 보여 준다. `summary_sections`는 각 장면의 `start_seq`, `end_seq`, `title`, `omitted_before`를 제공한다. 시간 순서를 유지하며 최대 128개 이내의 이벤트로 구성한다. `events_seen`은 실제 실행 중 발생한 이벤트 수다. 발생하지 않은 정답·종료는 만들지 않으며 제한으로 중단된 경우 도달한 범위만 보여 준다. 요약 구성 시간은 알고리즘 내부 실행 시간과 별도인 응답 준비 비용이다.

스냅샷으로 임의 단계와 이전 단계 복원이 가능하고 프론트엔드는 이벤트 종류와 필드에 따라 강조·설명을 그린다. 전체 기록이 잘린 경우 마지막 기록 이벤트를 탐색 완료로 표현하지 않는다. 브라우저는 `trace_view: "summary"`로 요청하며 이때 `trace`는 빈 배열이고 `trace_total`, `trace_token`, `summary_trace`, `events_seen`을 받는다. 전체 보기 선택 시 `GET /api/traces/<token>?offset=0&limit=200`으로 실제 실행 기록을 구간 조회한다. `trace_paged: true`, `trace_total: events_seen`으로 전체 재생 범위를 제공하며 페이지 응답은 `trace`, `offset`, `total`이다. 페이지 크기는 최대 500개다. 원본 스냅샷 버퍼의 상한 도달 여부는 `trace_buffer_limited`로 구분하고, 아카이브를 통한 전체 조회가 가능하므로 요약 응답의 `trace_truncated`는 false다. 최근 4개 실행, 실행별 10분의 프로세스 메모리 저장소를 사용하며 만료된 토큰은 `404 TRACE_EXPIRED`다. `trace_view`를 생략하거나 `full`로 요청하는 기존 API 호출은 전체 버퍼를 즉시 받는다. 레거시 즉시 반환 버퍼는 최대 80,000개 접두 이벤트다. 웹 전체 보기는 이 상한에 제한되지 않는다. `Feature/trace_archive.py`는 문제·실제 해·종료 상태·발생 이벤트 수를 기준으로 결정적인 실행을 복원한다. 완전탐색은 부분 트리의 이벤트 수와 실제 해의 위치로 직접 탐색하며, 백트래킹의 저장 범위 밖은 같은 순서를 재생한다. 실행 당시 도달한 이벤트 수를 넘는 후보는 노출하지 않는다. 전체 기록을 수백만 개의 JSON 객체로 메모리에 한꺼번에 보관하지 않는다. 기존 쿼리 없는 기록 조회는 초기 버퍼만 반환하는 호환 경로다. 비교의 기본 요청은 두 알고리즘을 순차 계산하고, 각 패널의 재풀이 버튼은 해당 알고리즘 하나만 새 요청한다.
