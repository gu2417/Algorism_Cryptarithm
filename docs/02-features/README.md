# 02. 기능 요구사항

> 모두 설계 단계이며 구현 완료를 의미하지 않는다. P0은 필수, P1은 필수 흐름 이후 구현한다.

## 입력 규칙

공백을 허용하고 소문자는 대문자로 정규화한다. 정규화 후 문법은 `WORD + WORD = WORD`, `WORD`는 하나 이상의 영문 대문자다. 단어 내부의 공백, 숫자, 다른 연산자, 괄호 및 추가 피연산자는 허용하지 않는다. 서로 다른 문자는 최대 10개이며 같은 문자는 같은 숫자, 서로 다른 문자는 서로 다른 숫자에 대응한다. 여러 자리 단어의 첫 문자는 0이 될 수 없다. 단일 문자 단어에는 0을 허용한다. 과도한 입력 방지를 위해 원문은 128자 이하로 제한하는 초기 설계다. 빈 문자열, 문법 오류, 문자 수 초과 및 길이 초과를 구별해 안내한다. 클라이언트 검사 후 서버에서도 동일 규칙을 독립적으로 검사한다.

## 기능 목록

| ID | 우선순위 | 입력 | 출력 | 수용 기준 |
|---|---|---|---|---|
| F01 직접 입력 | P0 | 수식 문자열 | 정규화된 문제 또는 오류 | `I + BB = ILL`, `SEND + MORE = MONEY`, 소문자·허용 공백을 처리하고 위반 규칙을 설명한다. |
| F02 예제 선택 | P0 | 예제 버튼 | 입력창의 수식 | 버튼은 입력만 채우며 실행 시 실제 서버 알고리즘을 호출한다. 정답과 재생 기록을 하드코딩하지 않는다. |
| F03 백트래킹 | P0 | 유효한 문제 | 해와 실제 실행 기록 | 자리별 제약을 적용해 해를 검증하고 전체 탐색 여부를 표시한다. |
| F04 완전탐색 | P0 | 유효한 문제 | 해와 통계 | 자리별 중간 가지치기 없이 유효한 전체 배정을 열거·검증하며 별도 제한을 적용한다. |
| F05 결과 | P0 | 풀이 응답 | 원문·숫자식·배정·해 수·통계·시간 | 해 없음, 여러 해, 제한으로 불완전한 결과를 구분한다. 완전 탐색일 때만 정확한 총 해 수를 표시한다. |
| F06 단계 시각화 | P0 | 선택한 알고리즘의 실행 기록 | 계산식·단계 설명 | 실제 이벤트 순서에 따라 후보, 배정, 검사, 복귀와 해를 표시한다. 백트래킹은 자리 계산과 올림을, 완전탐색은 완성된 전체 식 검사를 보여 준다. 비교 시 기록을 전환할 수 있다. |
| F07 재생 | P0 | 실행 기록, 사용자 조작 | 표시 중인 단계 | 실행/자동 재생, 일시정지, 이전·다음, 속도 조절, 처음부터 다시 보기가 동작한다. |
| F08 비교 | P1 | 동일 문제의 두 알고리즘 결과 | 해와 통계 비교 | 동일 정의의 측정값과 각 완료 상태를 표시하며 불완전 결과를 동등한 완전 결과로 비교하지 않는다. |
| F09 해 선택 | P1 | 반환된 여러 해 | 선택한 해의 배정·숫자식 | 반환된 해 중 선택 가능하며 기록은 전체 탐색 기록임을 표시한다. |

## 검증 계획

- 형식: 빈 입력, 잘못된 연산자, 숫자 포함, 소문자, 공백, 10개 초과 문자, 길이 초과를 검사한다.
- 정확성: `I + BB = ILL`, `SEND + MORE = MONEY`, 해 없음, 여러 해, 선행 0 가능성, 여러 자리 올림, 중복 배정을 검증한다. 두 알고리즘이 **모두 완료된 경우에만** 해 집합을 비교한다.
- 성능: 동일한 후보 배정 시도 기준의 횟수, 단조 시계 실행 시간, 알고리즘별 시간 제한, 기록 제한 및 해 제한을 검증한다.
- UI: 입력과 결과 연결, 이전/다음, 자동 재생·일시정지·속도·재시작, 오류 및 16:9 가독성을 확인한다.
